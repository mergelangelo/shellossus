# h-agent

Минимальный агент для Windows PowerShell 5.1 и OpenAI-совместимого Chat Completions API. Без Python, Node.js, Bash и дополнительных модулей.

## Что умеет первая версия

- Вести диалог с историей в памяти текущей сессии.
- Самостоятельно вызывать `list_files` и `read_file`, получать результат и продолжать рассуждение.
- Читать UTF-8 текстовые файлы: TXT, SQL, исходный код, CSV как обычный текст.
- Создавать новые текстовые файлы (`write_file`) и заменять один точный фрагмент в существующих (`edit_file`). Перед каждой записью показываются путь и полный текст до/после; для согласия нужно ввести `WRITE`, Enter отменяет запись.
- Ограничивать число запросов на один ход; `/clear` очищает историю, `/exit` завершает работу.

Это прототип, а не замена Pi по всем функциям. Выполнения команд, сохранения сессий, разбора PDF/DOCX/XLSX и автоматического сжатия истории пока нет. При заполнении контекста используйте `/clear`. Сервер должен поддерживать `tools` / `tool_calls`; потоковая выдача не нужна.

Запись ограничена 20 000 символов. Родительская папка должна существовать. `write_file` никогда не перезаписывает существующий файл. `edit_file` требует ровно одного совпадения с учётом регистра и сохраняет исходный файл в резервную копию в системной временной папке. Путь к копии показывается в терминале; удаляйте её вручную, когда она больше не нужна. При изменении файла во время подтверждения правка отменяется. Запись выполняется в UTF-8 (Windows PowerShell 5.1 добавляет BOM), без добавления завершающего перевода строки. Эти инструменты предназначены для текстовых файлов, а не бинарных документов.

Пример задания: «Создай notes.txt с текстом Привет». Для изменения: «В notes.txt замени Привет на Добрый день». Просмотрите предложение и введите `WRITE`, только если согласны. После ошибки API уже выполненные записи на диск не откатываются.

## Запуск в Citrix / Windows

1. Скачайте репозиторий через **Code → Download ZIP**, распакуйте архив.
2. Откройте уже имеющийся PowerShell и перейдите в папку с `h-agent.ps1`.
3. Запустите, подставив **свои** адрес, идентификатор модели и рабочую папку:

```powershell
.\h-agent.ps1 -BaseUrl "https://YOUR-SERVER/v1" -Model "YOUR-MODEL-ID" -Workspace "C:\Users\YOUR-NAME\Documents\agent-work"
```

Не добавляйте `/chat/completions` к BaseUrl: скрипт добавляет его сам. Ключ вводится после запуска, не сохраняется в файлы. Для совместимости с ограниченным режимом ввод обычный: **символы ключа видны на экране**. Не публикуйте этот экран и не вставляйте ключ в исходный код.

Можно запустить просто ` .\h-agent.ps1 `: скрипт спросит адрес и модель, рабочей папкой станет текущая. Для регулярного использования адрес и модель можно задать через `$env:H_AGENT_BASE_URL` и `$env:H_AGENT_MODEL`.

Первое задание:

> Посмотри файлы в рабочей папке. Затем прочитай hello.txt и кратко перескажи его содержимое.

На следующем ходе агент помнит диалог. На один ход выделено до 8 запросов к модели; настройка `-MaxSteps 12` меняет лимит (1–30).

## Ограничения корпоративной среды

Новых исполняемых файлов не требуется, но корпоративные правила могут запрещать и PowerShell-скрипты. Скрипт **не меняет ExecutionPolicy, режим языка и настройки безопасности**. Если `.ps1` запрещён политикой, используйте согласованный с ИТ способ запуска. Вставка исходного кода в открытую консоль возможна только если такой способ разрешён вашей организацией; не используйте её для обхода блокировки скриптов.

Код использует стандартные команды PowerShell и ориентирован на ConstrainedLanguage. Это не гарантия работы во всех конфигурациях Citrix/WDAC/AppLocker. Проверки в CI запускаются на Windows PowerShell 5.1, в том числе чтение файла в ConstrainedLanguage; корпоративная среда может вводить дополнительные ограничения.

## Данные и границы доступа

- Введённые сообщения, история и содержимое прочитанных файлов отправляются указанному API. Используйте разрешённый для этих данных сервер и отдельную рабочую папку.
- Чтение: список до 200 элементов; файл до 1 МиБ, первые 300 строк и 20 000 символов. Обрезанные результаты помечаются `truncated`. Запись требует отдельного подтверждения каждой операции; инструмента выполнения команд нет.
- Проверяется принадлежность пути рабочей папке; junction/symlink/reparse points в пути отвергаются. Это прикладная проверка, **не системная песочница** и не защита от одновременной подмены файлов другим процессом.
- После ошибки запроса текущий ход откатывается в локальной истории. Уже отправленные серверу данные это не удаляет.
- Сетевые запросы не повторяются автоматически. Сохраняется стандартная проверка TLS-сертификатов.
- Ключ очищается из переменной скрипта при выходе; гарантированное стирание из памяти не обещается.

## Проверки

На Windows, из папки репозитория:

```powershell
.\tests\smoke.ps1
```

Проверяются чтение файла, отклонение выхода за рабочую папку, неизвестный инструмент, неверный JSON, обрезка длинного файла, полный цикл API → инструмент → API на заглушке и чтение в ConstrainedLanguage. Настоящий API и ключ для проверок не нужны. Тест переключает текущую PowerShell-сессию в ConstrainedLanguage: запускайте его в отдельном окне. Автоматический запуск настроен в GitHub Actions.

Не добавляйте в репозиторий ключи, конфигурации с секретами или рабочие документы.
